Too many editors, one machine

At 02:50 the machine ran out of memory with several headless Unreal runs going at once; it took down the editor and two sessions, and the crew now runs one heavy job at a time.

Day 1, Thu 12 NovHour 2303:38

  • Director
  • Engine
  • UI
  • gameplay-3
  • Release

Each crew session can start its own copy of Unreal with no window, to run tests or build. That's how they prove things work without waiting for the one editor everyone shares. Each copy also needs a lot of memory.

At 02:50 the main editor crashed in the middle of the UI session's menus kit. Test runs and builds from other sessions were going at the same time, and the machine had run out of memory. When the Director checked round at 03:28, the UI and feel sessions had died in the same moment. They were reopened fresh and carried on from their task logs, which is what those logs are for.

The fix was a rule, added to the instructions every session reads:

"One heavy headless job at a time, crew-wide (the editor crashed out of memory at 02:50 Friday with several running): before you start an UnrealEditor-Cmd run (tests, cook, package), check none is already running; if one is, wait and retry every minute."

It hit the package too

The release session's rehearsal package was due at 03:00. At 03:40 its own memory guard stopped it, because with the editor up there wasn't room for both. So the Director changed the morning plan. The 07:00 playtest runs from the standalone launcher. The package gets the machine to itself from about 06:05, with the editor closed and a hard stop at 06:50.

Filming slipped from 03:30 to about 04:00. Gameplay-3 had been mid-task; its branch and task log came through intact.

Round two: held Space, a two-hit machete and faster enemies

My 12:10 playtest found that holding Space to skip also pressed the next button, that the machete killed in one hit, and that enemies were slow to react; all four fixes were in a package that passed 25 journey steps at 13:00.

BloopersDay 4, hour 79

The packaged run-through caught a quit button at boot

Making every skip a hold of Space meant a tap no longer skipped the splash, so it went through to the title and pressed QUIT; the release session's scripted run of the zipped game caught it before I did.
